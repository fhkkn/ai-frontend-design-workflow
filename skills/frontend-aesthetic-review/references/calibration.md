# 审美审核员训练与校准

本流程训练的是审核方法和证据使用，不是模型微调。分成“可选的个人偏好校准”和“真实项目美术建议复核”；前者不能替代后者，也不是开始审核的门槛。用户未要求继续时，不自动追加训练轮次。

## 1. 确定目标与记录边界

明确要改进的是哪类页面的风格判断、意见可执行性，还是对个人取舍的理解。约定样本范围、轮次或时间上限以及停点；数量按任务决定。例如可安排少量探索轮次后留出一批新作品复核，不将固定轮数当成能力认证。

复用已有私人状态、偏好和评审记录，只补充必要字段。写入前确认目录已获准、被 Git 忽略且没有相关已跟踪文件；非 Git 环境使用明确的私人存储位置。通用 skill 不内置任何人的选择和风格档案。

## 2. 成对观察与反馈

选取能实际查看、任务与设备尽可能接近的作品，记录来源、日期、版本或截图、视口与观察状态。避免只采一种营销页；按目标加入工具、内容页或应用界面。不要把应用宣传页当成应用实操界面。

获奖与评分可用于发现作品，不代表正确答案，也不能代替查看。原站不可达时可用已实际查看的官方案例画面，但注明不是当前原站；双方材料不足或无法观看时不计为有效比较。不人为弱化一方，也不因预测困难而换成更容易命中的作品。

尽可能保持查看顺序、时长和设备可比，随机或交替安排 A/B 展示顺序并记录；没有随机就如实注明。整页比较通常同时改变品牌、素材、布局和内容，须记录混杂，不能当单因素实验。

每轮中性地问一个可回答的问题，例如：“看过首屏与初步滚动后，整体更喜欢哪一个？也可以都喜欢、都不喜欢、无明显偏好或只喜欢某个局部。”原因可选，不诱导回答。第一观感、浏览后判断、整体偏好和局部亮点分开记录。不要把未答复记成同意。

## 3. 形成有限规则

将用户原话与审核员解释分开保存。每条候选规则记录证据来源、特征、适用情境、原因是否已知、反例、冲突、不确定性及版本。

只选了整页而没有解释原因时，保留选择事实，不补写配色、字体或动画偏好。少量一致只能提供有限支持；看似矛盾的反馈先检查任务与观察范围，不强行合成一种固定风格。专业判断、个人偏好和可核实的可用性问题分别记录。

## 4. 冻结并前瞻复核

在获取新一批答案前冻结规则版本，保留快照；可用内容哈希辅助核对未改动，但哈希本身不证明保存时间。选择未参与归纳的新作品，同一作品换色、裁切或相邻页面不能当作充分独立样本。

若测试偏好预测，每轮在用户作答前保存预测、理由、画面依据、所用规则、置信和相反可能，并保留时间或版本记录。向用户提问时不展示预测及倾向理由。固定批次中只追加答案，不改原预测与冻结规则，不因前一轮答错而迎合性选样。

批次结束后统一对照，保留分歧。无偏好或材料不足的案例单列，明确有效样本分母。除匹配数量外，比较简单基线（例如始终选 A），说明位置偏差、场景差异及样本规模限制。不用少数命中宣称稳定准确率，更不能据此证明美术审核能力。

据答案修改后的规则需要新的案例验证，不能以同批结果为新版本背书。主持人已见反馈、奖项或实现理由时说明上下文；事先保存预测不自动等于独立盲评。

## 5. 用真实项目检查美术建议

拿获准的真实页面，先按 SKILL.md 只读审查并保存原画面、意见和预期改善点。例如“标题与主图竞争焦点”应对应具体元素与视觉关系，而不是一个笼统审美分数。

经用户授权后实施选定建议，保留未采纳理由。在相同页面、视口和状态比较前后版本，检查预期视觉关系是否改善、原有亮点是否保留、是否出现新问题。尽量减少无关修改，避免无法分辨改善来自哪项建议。

结合用户判断及可用的独立评审意见，记录有用、无效或有副作用的建议，并区分风格偏好变化与建议本身的问题。没有独立参与者时标为自查；没有实施或查看改后画面时标为尚未验证，不编造训练成效。

## 6. 收束与续接

达到约定轮次或预算后，交付当前可用指令、证据支持的有限规则、反例、未验证能力和下一步。不要为了得到理想分数无限追加样本。后续按新反馈窄幅修订，不为每次失败增加一条普遍禁令。

续接时读取已有状态与规则版本，只处理尚未完成或用户新授权的部分。已完成的比较不因换会话而自动重启。公开交付通用方法，私人校准材料保留在私人位置。
