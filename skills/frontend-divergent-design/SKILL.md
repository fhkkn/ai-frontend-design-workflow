# 前端发散设计

用外部随机扰动打开设计空间，再通过真实画面和用户判断选择方向。随机性是探索方法，不是质量证明；“熵增”是这里的比喻，不是可测得的审美指标。

## 先确定边界与阶段

读取项目已有需求和设计决定。固定用户任务、真实内容、关键操作、必须保留的品牌约束及交付范围。只询问影响方向且尚未提供的信息，继续不依赖回答的准备工作。

根据当前阶段进入探索、选择或深化。用户已有明确方向或只要求局部修改时，直接按该方向工作；不要强行重新随机。用户授权自行选定时可以自主选择并说明理由；否则先展示候选，让用户选择后再深入实现。

## 生成扰动并转译

使用本 skill 的 `scripts/draw.py` 生成可追溯的组合。脚本只依赖 Python 标准库：

```sh
python scripts/draw.py --count 6
python scripts/draw.py --seed study-01 --count 6
```

命令中的路径相对于本 skill 目录；在别处运行时使用实际脚本路径。脚本输出种子、词库版本及来源、构图、表达和交互四个维度。相同脚本版本、种子和数量可复现抽取结果，不能保证复现模型输出。Python 不可用时使用其他可用的随机源并记录结果；手工构思时如实说明，不能声称已运行脚本。

把每组组合转译为与产品有关的设计假设：

- 这种来源的哪一种组织方法适合当前内容？
- 它会改变哪些内容的优先级、空间关系、字体或操作？
- 一个具体可见的识别特征是什么？
- 哪项随机约束不适配，如何替换或舍弃，理由是什么？

例如“植物标本册”可以启发条目编号、并列注释和分类关系，不意味着添加植物贴图。不要把词语原样贴进页面充当创意。

组合无法支撑任务时允许淘汰；不要为迁就随机词发明功能。既有材料和用户参考优先于词库，词库不应成为新的固定风格清单。

## 先做可见实验

从组合中挑选通常 3 个差异明显的候选，具体数量随用户范围和预算调整。优先产生不同结构的方案，其中可以有明显偏离常规但仍可理解的实验方向；不要求所有方案都复杂、装饰丰富或高成本。

先以真实内容制作浏览器可见的低成本代表区域。草图可以简化次要功能，但必须标明演示范围。不要先实现完整应用，也不要只交付风格名称和长篇创意说明。

比较时保持用户任务、主要内容与视口一致。至少从信息组织、构图、排版、素材语言或交互表达中的两个维度拉开差异；只换颜色和圆角不算新的方向。避免不同候选都落回同一种布局。不要人为弱化某个候选来证明推荐方案正确。

在浏览器中查看并保存截图。无法运行或检查时明确标为未验证。缺少工具时提供可审阅的替代草图，不能把未经查看的代码当成已验证视觉结果。

## 选择与深化

展示候选实际画面、核心假设与取舍，让用户描述喜欢和不喜欢的具体特征。若用户全部否定，根据反馈有针对性地重新探索；默认先完成一批，不无限抽取。时间或成本达到已约定上限时保存当前成果和未决项。

选定后记录 1–2 个必须保留的表达特征及其服务的任务。深化字体、比例、节奏、组件与必要交互，使它们共同支持该方向。不要把所有候选折中拼接，也不要在工程精修时无理由退回通用卡片布局。

可用性与基本可读性从探索时就保留，完整工程实现随选定方案推进。用户反馈与实际缺陷可以促成调整；“保护个性”不是保留难用设计的理由。

## 两条验收线

**视觉判断：** 是否能指出与任务相关的识别特征？去掉产品名称后，是否仍有具体表达？构图与阅读层级是否明确？是否只是机械采用参考或随机词？这些是判断问题，不设伪精确的审美总分。

**可用与工程验证：** 实际操作关键路径，检查适用状态、响应式、键盘和项目要求的检查。功能通过不能替代视觉方向确认，主观偏好也不能替代操作验证。

先修高影响问题，再分别做视觉减法与文案审阅。合理的渐变、卡片、对称布局和静态页面都可以保留，不建立风格禁用清单。

记录评审者与证据。实现者自己的判断标记为自查；独立评审只在有实际独立参与者时这样称呼，不因本 skill 自动派发其他任务。

## 留下可续接的结果

保存固定约束、种子与抽取结果、候选代码及截图、淘汰理由、用户选择、视觉规则、验证结果与未决项。过程记录按项目的隐私规则保存，公开内容只使用获准资料。探索草图不得覆盖未获准替换的现有成果。本 skill 不代表发布、付费服务或外部消息授权。
