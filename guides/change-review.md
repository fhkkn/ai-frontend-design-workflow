# 每轮改动审核

[project-change-review](../skills/project-change-review/SKILL.md) 用于修改后的质量审查，兼容本工作流仓库和使用它开发的前端项目。审美继续走现有视觉评审流程；工程审核不默认扩展为全仓架构审计。

## 接入

当前仓库的 [AGENTS.md](../AGENTS.md) 已约定每轮修改后读取该 skill。仓库中的 skill 文件可直接按路径读取；仅保存文件不代表已安装或实际执行过审核。

其他项目可复制 `skills/project-change-review/` 整个目录到项目选定位置，或安装到自己的 Codex skills 目录。不要覆盖已有同名 skill 或 AGENTS.md。将下列最小规则合并到目标项目已有约定中，并替换为实际 skill 路径；保留其技术栈、命令、设计规范和隐私规则：

```text
每轮修改前确认基线和已有改动归属；完成后读取【审核 skill 的 SKILL.md 路径】，
按本轮需求、实际差异和验证证据做只读审核，复用已有任务及验收记录。
实现者审核标为自查；结果说明范围、发现和未验证部分，不自动修复或批准合并。
```

Codex 的指导文件在运行开始时加载，项目根到工作目录的规则按顺序合并，同目录的 AGENTS.override.md 优先于 AGENTS.md；加载也有大小限制。新增规则后在新会话核对实际加载来源，已有会话可明确要求读取文件。详见 [OpenAI 官方 AGENTS.md 文档](https://developers.openai.com/codex/guides/agents-md/)。这是行为约定，不是强制阻止越界修改的权限机制。

## 一次具体调用

修改前在已有任务记录中保留基线、起始工作区状态和其他改动归属。干净工作区可记录提交号；已有未提交改动需保存前快照或补丁，不能只提供 HEAD。不要为了获得干净基线而回滚或暂存他人的工作。

下面是“修复搜索框按 Enter 提交”的示例，替换括号后使用。已安装且当前会话可发现时可用 `$project-change-review`；否则明确读取项目中的 SKILL.md：

```text
请读取【审核 skill 路径】并只读审核本轮修改。
需求：搜索框按 Enter 应调用与点击搜索按钮相同的提交逻辑，保留空查询提示。
已确认决定、任务与验收记录：【现有记录位置】。
改动前基线：【提交号；或含原有未提交内容的前快照】。
本轮改动范围与其他改动归属：【文件／差异说明；不明处注明】。
当前版本：【提交号或当前工作区快照标识】；验证证据：【实际输出位置】。
请直接检查实际差异、新文件及必要调用方，不只依据完成总结。
报告确认问题、待核实风险及结论；不要修复，不作发布或合并批准。
```

本仓库的文档任务也用同一方式调用，将需求换成实际文档改动目标即可，不需要另建审核模板。复核时沿用原基线并提供新版本和新验证证据。独立评审须有实际独立参与者；同一实现者换角色仍是自查。
