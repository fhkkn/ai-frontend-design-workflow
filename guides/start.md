# 按任务选择路线

开始前先说明：页面用途、目标用户、主要任务、交付级别和必须保留的行为。没有真实资料的部分写“待确认”。

| 任务 | 准备什么 | 执行顺序 | 最少交付 |
| --- | --- | --- | --- |
| 首次设计 | 需求、内容、少量参考、技术约束 | 简报 → 候选方向 → 选定方向 → 代表页面 → 验证与评审 → 扩展 | 简报、视觉规范、代表页面、验证记录 |
| 已有项目改版 | 当前页面、现有规范、具体问题、需要保留的路径 | 检查现状 → 界定问题 → 局部方案 → 修改 → 回归 | 修改范围、前后截图、受影响路径的验证 |
| 新增页面 | 现有组件、页面地图、新内容和适用状态 | 读规范 → 内容建模 → 复用组件 → 实现 → 验证 | 新页面、状态说明、必要的规范补充 |

## 首次设计：复制指令

```text
参考本项目手册和 templates/，为【产品】完成【页面或路径】。
目标用户：【填写】；核心任务：【填写】；交付级别：【填写】。
技术及业务约束：【填写】；内容与参考资料：【填写】。
先建立 brief、status，提出差异明确且规模适当的候选方向。
沿用已获得的授权；方向尚未确认时，先完成不依赖选择的工作。
随后制作代表页面，用实际截图和操作记录评审与验收，再扩展范围。
```

## 已有项目改版：复制指令

```text
请改善【页面】的【具体问题】，保留【业务行为、风格、接口】。
先读现有规则，检查当前页面并保留基线截图。
说明本轮修改范围与完成标准，然后实现和验证。
只有现有方向无法承载需求时才提出重新探索，不默认重做全站。
公共组件有变化时，回归依赖它的代表页面。
```

## 新增页面：复制指令

```text
在现有项目新增【页面】，主要任务为【填写】，内容和状态为【填写】。
先读取现有设计规范和相邻页面，优先复用组件。
实现适用的加载、空、错误、成功状态，并验证响应式和核心操作。
新增公共规则才更新设计规范；记录未接入能力和剩余问题。
```

## 控制流程成本

小改动使用一张任务卡和必要验证即可。新视觉方向先做少量低成本候选；只有候选雷同或决策仍不清楚时扩大探索。评审发现的问题修复并复核后即可结束，不为满足轮数强制修改。手册里的方向数量和轮次是管理参考。

首次采用可先复制 [brief](../templates/brief.md)、[visual-brief](../templates/visual-brief.md)、[status](../templates/status.md)、[acceptance](../templates/acceptance.md) 到实际项目的 `docs/design/`。不要将填写了客户资料的文件直接提交回本公开模板库。

## 续接指令

```text
读取本项目 status 及其引用的规范和验证记录，核对实际文件与记录。
保留已有修改，沿用已确认的方向和授权，继续最高优先级未完成项。
结束时记录本轮完成内容、证据、限制和下一步。
```
