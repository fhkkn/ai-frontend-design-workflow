# 使用与训练审美审核员

[前端美术与风格审核 skill](../skills/frontend-aesthetic-review/SKILL.md) 用于审查已有画面的视觉方向、构图、字体、色彩、素材、动效和风格完成度，帮助发现保守、平庸或表达不完整的具体原因。它给出建议，默认不修改产品。

## 与已有流程配合

- 探索新方向：使用 [前端发散设计](../skills/frontend-divergent-design/SKILL.md)，制作实际候选并选定方向。
- 审查美术与风格：使用本 skill，先看真实画面，给出保留项、具体改法与复核点。
- 审查修改的必要性、范围、事实及回归风险：使用 [项目改动审核员](change-review.md)。功能和工程验收不代替美术判断。

沿用项目已有设计规范、任务和评审记录，不需要建立第二套项目文档。个人偏好档案是可选参考，不是使用门槛；公开版不包含私人选择、聊天或训练成绩。

## 一次审核

将 `skills/frontend-aesthetic-review/` 完整目录复制到项目选定位置，或自己的 Codex skills 目录，保留 `references/calibration.md`。已有同名目录先比较合并，不直接覆盖。当前会话未发现技能时，明确要求按路径读取即可；不必改写项目已有 AGENTS.md。

```text
请读取【frontend-aesthetic-review/SKILL.md 的实际路径】，只读审查前端美术与风格。
页面用途及预期气质：【填写】；已有设计规范：【位置或说明】。
当前页面／截图与实现版本：【填写】；目标设备及审查范围：【填写】。
先看真实画面，判断方向是否成立，再给保留亮点与少量重要美术改进。
每项说明位置、画面证据、影响、具体改法和改后检查点。
不要把常见组件自动判为模板化，也不要为大胆而堆效果。
标明实际覆盖与未验证部分，不修改产品。个人偏好仅在我提供时作为辅助。
```

如需独立评审，使用实际独立参与者和最小输入包；同一实现者换角色仍是自查。修改需另有授权，复核使用新版本的实际画面。

## 训练与校准

完整步骤见 [训练流程](../skills/frontend-aesthetic-review/references/calibration.md)：确定目标与上限 → 成对观察 → 保存反馈与有限规则 → 冻结版本 → 新案例事先判断 → 对照与修订 → 真实项目改前改后复核。

```text
请读取【frontend-aesthetic-review/SKILL.md 的实际路径】及其训练流程，
为【目标页面类型】校准审美审核方法。时间或轮次上限：【填写】。
私人记录位置：【填写；先核对忽略与跟踪状态】；已有状态和规则：【如有】。
用真实可见、任务接近的作品比较，区分整体判断、局部亮点与第一观感。
先保存预测再获取新案例答案；保留分歧，不修改冻结预测。
最终说明哪些判断有依据、哪些仍未知；不要把偏好命中当作美术能力证明。
真实项目建议的效果需另用获准修改后的画面对照，不自动改产品或追加轮次。
```

这里的“训练”是积累证据与改进指令，不是模型权重训练。方法文件和结构检查不能证明审核员已能稳定提升设计质量；实际效果需要在具体项目中检验。
